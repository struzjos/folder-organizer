## Context
The goal is a small, easy-to-use desktop widget (Python + Qt) that shows **buttons that open File Explorer on a specific folder**. There are two kinds of buttons:
- **Permanent**: always shown. **Every change is saved to a permanent history** (one snapshot per change), so any earlier version can be viewed and restored.
- **Daily**: a per-day list of folder buttons. A new "day" starts at a configurable time (default 04:00). Every day is saved to history, so any previous day can be loaded again. If today has no folders yet, the widget shows a button that loads the most recent previous day.

Every button has a **custom name**, separate from the folder name. Project trees often contain folders with the same name, such as `ProjectA\renders` and `ProjectB\renders`, so the name has to tell them apart.

`D:\Dev\FolderOrganizer` is currently empty (no git repo). Python 3.13 is installed (`py -3.13`).

Decisions confirmed with the user:
- Daily = a per-day **list of buttons** (no folders are created on disk).
- Add buttons by **drag & drop** of a folder and with a **"+" button that opens a folder picker**.
- Every button has a **user-defined name**. When you add a folder, you're asked for the name, and the default tells apart folders with the same name.
- Permanent buttons have **change history**: every add, remove, rename, move or reorder saves a snapshot.
- Window = **small frameless panel + system tray icon**. It can be dragged, it remembers its position and it has an optional always-on-top setting.
- Qt binding = **PySide6**.

## Core logic

**`day.py`**
- `logical_date(now: datetime, reset: time) -> date`: returns `(now - timedelta(hours=reset.hour, minutes=reset.minute)).date()`. With the default 04:00 reset, 02:30 on Oct 10 still counts as Oct 9.
- `next_reset(now, reset) -> datetime` is used to schedule the rollover.

**First run / bootstrap** (`config.ensure_config()`, called first in `__main__.py` before any Qt code):
- If `config/` doesn't exist, it is created.
- If `config/settings.toml` doesn't exist, the template `src/folder_organizer/default_settings.toml` is copied there. The template has comments explaining every option. The template is the single source of defaults, so the app and the generated file always agree.
- `data/`, `data/daily/` and `data/permanent_history/` are created, along with empty `permanent.json` and `state.json`.
- Existing files are never overwritten. If the user deletes `settings.toml`, it is recreated on the next start. If a key is missing from the user's file, the template value is used, so old config files keep working after new options are added.
- If `settings.toml` can't be parsed, the app starts with the defaults and shows a tray or message-box warning naming the file and line. It does not overwrite the broken file.
- `config/settings.toml` is listed in `.gitignore`, because it is personal. The template in `src/` is what's committed.

**`config.py`**: `settings.toml` contents (= `default_settings.toml`):
```toml
[day]
reset_time = "04:00"

[window]
always_on_top = false
opacity = 0.95
width = 520
layout = "horizontal"    # "horizontal" = side by side, "vertical" = stacked
permanent_side = "left"  # "left" | "right" (or "top" | "bottom" when vertical); Daily goes on the other side
start_hidden = false     # start minimized to tray

[storage]
data_dir = "data"        # relative to project root

[permanent_history]
max_snapshots = 1000     # oldest snapshots are deleted beyond this; 0 = keep all
```

**`storage.py`**: plain JSON with atomic writes (temp file + `os.replace`).
- Entry format everywhere: `{"label": "A – renders", "path": "D:\\Projects\\A\\renders", "added_at": "..."}`. `label` is the custom name shown on the button.
- `load_permanent()` reads the current list.
- `save_permanent(entries, action: str)` writes `permanent.json` **and** a snapshot `permanent_history/<timestamp>.json` = `{"timestamp", "action", "entries"}`. `action` is a short description such as `added "A – renders"`, `renamed "renders" → "B – renders"`, `removed …`, `reordered`, or `restored snapshot <ts>`. If the list didn't actually change, no snapshot is written. When there are more than `max_snapshots`, the oldest are pruned.
- `list_permanent_snapshots() -> list[PermanentSnapshot]` (newest first) and `load_permanent_snapshot(ts)`.
- `restore_permanent(ts)` saves that snapshot's entries as the current list via `save_permanent(..., action="restored …")`. A restore therefore becomes a new snapshot and can be undone.
- `load_day(date) / save_day(date, entries)` reads and writes `daily/YYYY-MM-DD.json` in the format `{"date": ..., "entries": [...]}`
- `list_days() -> list[date]` returns the days that have a non-empty history file, sorted.
- `last_nonempty_day_before(date) -> date | None`
- `load_state() / save_state()` stores the window position and similar values.

**`naming.py`**: `suggest_label(path, existing_labels) -> str`
- It starts with the folder name (`renders`).
- If another entry in the same section already uses that name, it prepends parent folders until the name is unique: `ProjectB / renders`, then `Clients / ProjectB / renders`.
- This is only the pre-filled suggestion. The user can type any name. Duplicate names are allowed, but the dialog shows a warning.

**`explorer.py`**: `open_folder(path)` calls `os.startfile(path)`. If the path no longer exists, it shows a warning instead.

## UI behavior
- **Frameless panel** (`Qt.FramelessWindowHint | Qt.Tool`). The header is the drag handle and holds a title, a pin (always-on-top toggle) and a hide-to-tray button. The window position is saved to `state.json` when it moves or closes.
- **Tray icon** (`QSystemTrayIcon`): left-click toggles show/hide. The menu has Show, Open config folder, Open data folder and Quit.
- **Layout: two columns side by side** in a `QSplitter`, so the user can drag the divider. By default **Permanent is on the left and Daily is on the right**. Both are configurable through `window.layout` and `window.permanent_side`. Invalid values fall back to the default and log a warning. The splitter sizes are saved to `state.json`. Each column scrolls vertically when it has many buttons. The default window width is about 520 px (`window.width`).
- **Permanent section** (left) and **Daily section** (right), each a `FolderSection`:
  - A vertical list of `FolderButton`s. Each shows its **custom name**, and the tooltip shows the full path.
  - The "+" button opens the folder picker and then the **Name dialog** (`entry_dialog.py`). The dialog has a Name field pre-filled with `suggest_label(...)` and a read-only Path field. Enter confirms and Esc cancels.
  - Dropping a single folder from Explorer opens the same Name dialog. Dropping several folders adds them all at once with their suggested names, which can be renamed later. If a file is dropped, its parent folder is added. The same path can't be added twice to one section.
  - Button context menu: Open, **Edit… (name and path)**, Copy path, Move to Permanent/Daily, Remove. Buttons can be reordered by dragging within a section.
  - Buttons whose path no longer exists are shown greyed out with a "missing" tooltip.
- **Permanent history**: the Permanent section header has a **History** button (clock icon) that opens `permanent_history_dialog.py`.
  - The left side lists the snapshots, newest first, showing the time and action.
  - The right side previews that snapshot's buttons (name and path).
  - **Restore** replaces the current permanent list. You confirm first, and the restore itself is recorded as a new snapshot.
- **Day navigator** (in the Daily section header): `◀ [date combo] ▶ [Today]`. The combo lists `list_days()` plus today. You can view any past day and edit it. The section title shows "Today" or the date.
- **Empty today**: when today is shown with no entries, the section shows a button **"Load previous day (YYYY-MM-DD)"** that copies the entries of `last_nonempty_day_before(today)` into today and saves them. This button is hidden when there is no history.
- **Day rollover**: `app.py` runs a `QTimer` every 60 s that compares `logical_date(now)` with the current one. Checking every minute also catches sleep and resume. When the day changes and the user is viewing "today", the view switches to the new (empty) day, which then shows the "Load previous day" button. If the user is viewing a past day, the view stays there.

## run.bat
```bat
@echo off
setlocal
cd /d "%~dp0"
if not exist ".venv\Scripts\python.exe" (
    py -3.13 -m venv .venv || python -m venv .venv
)
rem reinstall deps only when requirements.txt changed
fc /b requirements.txt .venv\requirements.installed >nul 2>&1 || (
    ".venv\Scripts\python.exe" -m pip install -r requirements.txt && copy /y requirements.txt .venv\requirements.installed >nul
)
set "PYTHONPATH=%~dp0src"
start "" ".venv\Scripts\pythonw.exe" -m folder_organizer %*
```
It uses `pythonw.exe`, so no console window stays open. For debugging, run `.venv\Scripts\python -m folder_organizer` with `PYTHONPATH=src`.
